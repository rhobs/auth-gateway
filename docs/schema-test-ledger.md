# Schema-to-test ledger

The checked-in [configuration reference](configuration-reference.md) has 145 field rows. Every row is accounted for below, including object and list fields. Field suffix rows use the parent contexts named in the reference: route timeouts apply to API and route timeouts, HTTP/2 options apply to listener and upstream HTTP/2 settings, and circuit breakers apply to APIs and JWKS clusters.

Unit evidence includes loading, defaults, and validation. Generated-output evidence covers the Envoy files, ECDS processing files, or Kubernetes resources. The shared golden check is [TestGeneratedReferenceFiles](../config/generate_test.go), which compares each checked-in fixture with its generated Envoy, processing, and Kubernetes output. A live request is listed only where the option changes behavior visible to a client. "No separate request" means the artifact assertion is the relevant gateway contract; Envoy-only tuning behavior stays outside gateway e2e tests as required by AGENTS.md.

## Security request decision matrix

A denied request must leave the backend request count unchanged. The expected statuses below are the contract for each branch. A valid signed JWT with a wrong audience currently returns 403 with the pinned Envoy, and the JWT e2e case records that observed status.

| Request decision | Expected result | Current request evidence |
| --- | --- | --- |
| Public server, no credential, bound route | 200; delivered to httpbin. | [HTTP routing](../e2e/http_test.go) and the public host in [API-key scenarios](../e2e/api_keys_test.go). |
| One selected JWT or key, valid credential and grant | 200; delivered. Missing or invalid credential is 401; valid credential with a denied grant is 403. Both denials stay out of httpbin. | [JWT](../e2e/jwt_test.go), [API-key](../e2e/api_keys_test.go). |
| Two selected JWTs under any_of | Either selected issuer with a grant returns 200 and is delivered; a missing or invalid credential, or an issuer not selected on that server, returns 401 and is not delivered. A selected issuer with a valid token but no grant returns 403 and is not delivered. | [JWT issuer isolation](../e2e/jwt_test.go). |
| JWT plus key under any_of | A valid JWT takes precedence; a valid key is the fallback when JWT verification fails. Accepted branches return 200 and reach httpbin; neither valid credential returns 401; a valid but unprivileged JWT returns 403 even if a key is also supplied. Denials are not delivered. | [Mixed API-key any_of](../e2e/api_keys_test.go), [header any_of](../e2e/header_attributes_test.go). |
| JWT plus key under all_of | Both valid credentials and equal nonempty scalar attributes return 200 and reach httpbin. A missing/invalid credential returns 401; mismatched, empty, or nonscalar shared values return 403. Denials are not delivered. | [API-key all_of](../e2e/api_keys_test.go), [header all_of](../e2e/header_attributes_test.go). |
| Valid authentication on a protected server with no selected policy | 403; not delivered. | A valid JWT receives 403 and the upstream counter stays unchanged in [Plain JWT authorization](../e2e/jwt_test.go). |
| Multiple selected policies | any_of returns 200 if one selected policy grants. all_of returns 403 if any selected policy vetoes. The denied request must not be delivered. | An authenticated request with one grant and one veto is allowed by any_of; all_of denies it before httpbin. Both-grants acceptance is also checked in [Plain JWT authorization](../e2e/jwt_test.go). |
| Two JWTs plus a key under any_of | Either selected JWT or the key with a grant returns 200 and reaches httpbin. An invalid JWT with a valid key falls back to the key. An unselected issuer without a valid fallback and spoofed issuer markers return 401 and are not delivered. | [Three-credential API-key selector](../e2e/api_keys_test.go) checks both issuers, key fallback, unselected issuer, spoofed markers, mapped identity, and upstream delivery. |
| Valid signature with a future nbf claim | 401; not delivered. | A signed token with future nbf is rejected with 401 before httpbin in [Plain JWT authorization](../e2e/jwt_test.go). |

Invalid configuration selectors have no HTTP status: Load or Validate rejects them before Envoy generation. The validation table covers empty selectors, both selectors set, duplicate or unknown names, authorization without authentication, multiple JWTs under all_of, duplicate selected JWT issuers, and duplicate API-key authenticator configuration.
